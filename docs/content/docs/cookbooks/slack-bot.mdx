---
title: Slack bot
description: A Slack Bolt bot that remembers across threads — mapping Slack's user and thread ids onto Memsy actors and sessions.
---

Slack is where most teams already have their institutional memory, and where it is least retrievable. A bot that answers questions from the team's own history turns that scrollback into something you can ask.

The integration point here is **the identity mapping**. Slack has no notion of a "session", and a naive port either gives every message its own session (losing all multi-turn context) or shares one session across the whole workspace (blending unrelated conversations). Slack's own threading model is the right boundary, and this recipe uses it.

<Note>
If you only want Slack **content** in Memsy — no bot, no code — the [Slack connector](/docs/connectors#slack) ingests public channels from the console. This recipe is for the other case: a bot that answers in Slack and records its own conversations.
</Note>

<Steps>
  <Step title="Install dependencies">
    ```bash
    pip install memsy slack-bolt openai
    ```

    Python 3.10 or later.
  </Step>

  <Step title="Create the Slack app">
    At [api.slack.com/apps](https://api.slack.com/apps), create an app and enable **Socket Mode** (no public URL needed for local development). Then:

    - **OAuth & Permissions** → bot token scopes: `app_mentions:read`, `chat:write`, `channels:history`
    - **Event Subscriptions** → subscribe to the bot event `app_mention`
    - Install to your workspace, then copy the bot token (`xoxb-…`) and an app-level token with `connections:write` (`xapp-…`)

    ```bash
    export SLACK_BOT_TOKEN="xoxb-..."
    export SLACK_APP_TOKEN="xapp-..."
    export MEMSY_BASE_URL="https://api.memsy.io/v1"
    export MEMSY_API_KEY="msy_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
    export OPENAI_API_KEY="sk-..."
    ```

    <Warning>
    A bot token grants read access to every channel it is invited to. Keep all four of these in your secret manager, never in the repo.
    </Warning>
  </Step>

  <Step title="Map Slack ids onto Memsy ids">
    This is the whole design decision, so it gets its own module.

    ```python
    # identity.py
    from typing import Any


    def actor_id(event: dict[str, Any]) -> str:
        """Who is speaking. Slack user ids are stable for the life of the account."""
        return f"slack_{event['user']}"


    def session_id(event: dict[str, Any]) -> str:
        """
        Which conversation. `thread_ts` is present on every message inside a
        thread; a top-level message has only `ts`, and becomes the root of the
        thread the bot's reply creates. Falling back to `ts` therefore gives the
        thread and its root message the same session id — which is correct,
        because they are the same conversation.
        """
        return f"slack_{event['channel']}_{event.get('thread_ts', event['ts'])}"
    ```

    | Slack concept | Memsy concept | Why |
    |---|---|---|
    | User id (`U…`) | `actor_id` | Stable, unique, and never reused |
    | Thread (`thread_ts`) | `session_id` | One thread is one conversation |
    | Channel (`C…`) | part of `session_id` | Keeps two threads in different channels distinct |
    | Display name | *nothing* | Users rename themselves; ids do not change |

    <Warning>
    Do not use the display name or email as `actor_id`. A rename or an address change silently orphans every memory recorded under the old value — the bot does not error, it just forgets that person.
    </Warning>
  </Step>

  <Step title="Handle the mention">
    Bolt's default (non-async) `App` runs handlers on a thread pool, so the synchronous `MemsyClient` is the right client here — unlike in an async framework such as [FastAPI](/docs/cookbooks/fastapi-support-agent).

    ```python
    # app.py
    import logging
    import os
    import re

    from memsy import EventPayload, MemsyClient
    from memsy.exceptions import MemsyError
    from openai import OpenAI
    from slack_bolt import App
    from slack_bolt.adapter.socket_mode import SocketModeHandler

    from identity import actor_id, session_id

    logging.basicConfig(level=logging.INFO)
    log = logging.getLogger(__name__)

    memsy = MemsyClient(
        base_url=os.environ["MEMSY_BASE_URL"],
        api_key=os.environ["MEMSY_API_KEY"],
    )
    openai = OpenAI()
    app = App(token=os.environ["SLACK_BOT_TOKEN"])

    # "<@U123ABC> what did we decide?" -> "what did we decide?"
    MENTION = re.compile(r"<@[A-Z0-9]+>")


    @app.event("app_mention")
    def handle_mention(event, say):
        question = MENTION.sub("", event["text"]).strip()
        if not question:
            say(text="Ask me something.", thread_ts=event.get("thread_ts", event["ts"]))
            return

        actor = actor_id(event)
        session = session_id(event)

        # 1. Recall. Scoped to this person — see the note below on team-wide recall.
        try:
            recalled = memsy.search(question, actor_id=actor, limit=5, threshold=0.3)
            memories = [r.content for r in recalled.results]
        except MemsyError:
            log.exception("memsy recall failed")
            memories = []

        context = "\n".join(f"- {m}" for m in memories) or "(no prior context)"

        # 2. Ground.
        completion = openai.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {
                    "role": "system",
                    "content": (
                        "You are a helpful teammate in Slack. Be brief — two or "
                        "three sentences. Use the prior context below when it is "
                        "relevant.\n\n"
                        f"Prior context:\n{context}"
                    ),
                },
                {"role": "user", "content": question},
            ],
        )
        answer = completion.choices[0].message.content or ""

        # Reply in-thread so the conversation stays one session.
        say(text=answer, thread_ts=event.get("thread_ts", event["ts"]))

        # 3. Record.
        try:
            memsy.ingest(
                [
                    EventPayload(
                        actor_id=actor,
                        session_id=session,
                        kind="user_message",
                        content=question,
                    ),
                    EventPayload(
                        actor_id=actor,
                        session_id=session,
                        kind="assistant_message",
                        content=answer,
                    ),
                ]
            )
        except MemsyError:
            # The reply is already in the channel; a failed write must not
            # produce a second, confusing error message in the thread.
            log.exception("memsy ingest failed")


    if __name__ == "__main__":
        SocketModeHandler(app, os.environ["SLACK_APP_TOKEN"]).start()
    ```
  </Step>

  <Step title="Run it">
    ```bash
    python app.py
    ```

    Invite the bot to a channel and mention it. Reply in the same thread and it carries the context; start a new thread and it starts a new session — but still recalls what you told it in the old one, because recall is scoped to the actor, not the session.
  </Step>

  <Step title="Optional: recall across the whole team">
    Per-actor recall means the bot remembers *you*. Often what a team actually wants is for it to remember *the team* — so a question about a decision surfaces the answer whoever made it.

    Tag events with a team at ingest time:

    ```python
    EventPayload(
        actor_id=actor,
        session_id=session,
        kind="user_message",
        content=question,
        team_id=f"slack_{event['channel']}",   # the channel is the team
    )
    ```

    Then pass the team on recall, which widens results to include team-promoted memories:

    ```python
    recalled = memsy.search(
        question,
        actor_id=actor,
        team_ids=[f"slack_{event['channel']}"],
        limit=5,
    )
    ```

    <Warning>
    This makes one person's messages reachable by everyone else in the channel. That is the point in a shared channel, and a privacy incident in a DM. Gate it on `event["channel_type"]` if your bot handles both.
    </Warning>
  </Step>
</Steps>

## What to watch for

- **Replying outside the thread.** Omitting `thread_ts` on `say()` posts to the channel root, which starts a new Slack thread — and the next message arrives with a different `session_id` than the one you just wrote.
- **Slack's 3-second ack.** Bolt acknowledges the event for you before your handler runs, so a slow LLM call will not cause Slack to retry. If you move to a custom HTTP adapter, ack first and do the work after.
- **Bot messages echoing back.** `app_mention` only fires on mentions, so the bot does not hear itself. If you widen to `message` events, filter on `event.get("bot_id")` or you will ingest an infinite loop of the bot's own replies.
- **Display names as ids.** Covered above, and worth repeating: it fails silently.
